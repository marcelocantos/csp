## Findings

### ENT-001: Windows/CMake compile graph silently drops protocol TUs

- **Priority:** P1
- **Dimensions:** Architecture topology; Change amplification; Correctness / verification; Build / release / operations
- **Status:** observed fact
- **Evidence:**
  - CMake `LIB_SRCS` lists `src/http.cc` but never `http2.cc`, `ws.cc`, `http3.cc`, or `quic.cc` (`CMakeLists.txt:101-122`). `CSP_TLS` adds only `src/tls.cc` (`CMakeLists.txt:140-142`).
  - Makefile Unix graph compiles `http2.cc`, `ws.cc`, `http3.cc`, and TLS-gated `quic.cc` (`Makefile:485-492`).
  - Windows CMake tests explicitly filter those suites plus `http.test.cc` (`CMakeLists.txt:230-241`).
  - Cloud Windows job configures `-DCSP_TLS=OFF` (`.github/workflows/ci.yml:444-457`). `scripts/win-validate.sh` drives the same CMake/MSVC path on the VM.
  - 🎯T46 acceptance claims Windows `#else` self-connect and `http2::serve("127.0.0.1", 0)` fixes in `src/http2.cc` (`bullseye.yaml:1355-1361`). Those branches are never compiled by CMake, so the Windows-specific http2 repair cannot run on Windows.
  - README advertises HTTP/2, HTTP/3, WebSocket, QUIC and “Cross-platform — … Windows” (`README.md:19`, `README.md:29`).
- **Mechanism:** two hand-maintained source lists. A protocol TU added to Makefile + amalgamate `protocol_specs` is still absent from the only Windows build. Windows `#ifdef`s inside those files become uncompiled residue. Future protocol bugs will be “fixed” on Unix and invisible on the Windows gate.
- **Blast radius:** every Windows consumer of the CMake build; `win-validate` full suite; cloud `windows` job. HTTP/2+ on Windows is an undocumented product hole, not a skipped test.
- **Counterevidence checked:** CMake comments say nghttp2/wslay/nghttp3 “not wired through CMake yet” — the gap is acknowledged locally, not in the public feature list. Hygiene `correctness.windows` describes TLS unported, not the HTTP/2+ omission. T23 DCE is Makefile/`dist/` only.
- **Smallest coherent remediation:** make CMake `LIB_SRCS` a function of the same protocol list the Makefile and `amalgamate.py` already share (one table). Either compile http2/ws/http3/quic on Windows or delete Windows branches from those TUs and state the subset in README/`STABILITY.md`/hygiene.
- **Verification:** a CMake configure+build that fails if `src/http2.cc` (etc.) exists and is not in the target, plus one Windows (or cross) link of `http2::serve`. Inverse: a test that `nm`/`dumpbin` on `csp.lib` lacks `http2` when the subset is declared.
- **Ratchet candidate:** architecture test or `scripts/lint_frontdoor.py` sibling: `src/*.cc` minus protocol/globals/win-only must equal Makefile `LIB_SRCS` and CMake `LIB_SRCS` (with an explicit Windows-omit allowlist if the subset is accepted).

### ENT-002: Sanitizer and dist oracles do not run protocol tests

- **Priority:** P1
- **Dimensions:** Correctness / verification
- **Status:** observed fact
- **Evidence:**
  - `Makefile:495-522` filters `test/net.test.cc`, `http.test.cc`, `http2.test.cc`, `http3.test.cc`, `ws.test.cc`, `quic.test.cc` (and several stack white-box tests) when `CSP_INCLUDE=dist`, because those tests `#include <csp/net.h>` etc. which do not exist as files in the drop-in.
  - Comment at `Makefile:501-502` calls fixing this “follow-up work (sub-target of 🎯T23)”. T23 and T23.1–T23.4 are **achieved**; no remaining target owns the follow-up.
  - CI sanitizer job runs only `make test-dist SANITIZE=…` (`.github/workflows/ci.yml:320-323`). The source-layout `make` on the `test` job runs protocol tests **without** sanitizers.
- **Mechanism:** two include layouts. The shipped header is one file (`dist/csp.h`); protocol tests still address the development tree. Sanitizers therefore never execute HTTP/WS/QUIC tests against the artefact users compile. Amalgamation bugs in protocol headers (include order, macro leakage, missing inline) are invisible to ASan/TSan/UBSan.
- **Blast radius:** all protocol drop-in consumers; any amalgamation regression in `http.h`/`ws.h`/`quic.h`/`http2.h`/`http3.h`/`net.h`.
- **Counterevidence checked:** dist still *compiles* `dist/csp_http.cpp` etc., so link/parse of those TUs is covered. `subset-link` checks DCE, not behaviour. Source-layout `make` on macOS/Linux still runs protocol tests (non-sanitized).
- **Smallest coherent remediation:** change protocol tests to `#include "csp.h"` (or a test shim that maps `<csp/net.h>` → `csp.h` when `CSP_INCLUDE=dist`) and stop filtering them. Keep stack-pool white-box tests source-only if they need `csp::detail`.
- **Verification:** `make test-dist` test count includes `http`/`ws`/`quic` cases; sanitizer job fails if those tests are filtered. A ratchet file listing expected doctest names for dist vs source.
- **Ratchet candidate:** CI step comparing `csp_tests --list-test-cases` under `CSP_INCLUDE=include` vs `dist` for the protocol suite; fail on a name disappearing from dist.

### ENT-006: `cancel_reason()` publishes `exception_ptr` without a happens-before edge

- **Priority:** P2
- **Dimensions:** Local code quality; Correctness / verification
- **Status:** observed fact (accesses); inference (user-visible miss or TSan race)
- **Evidence:**
  - `src/cancel.cc:24-28`: `cancelled.exchange(true)` then plain `reason = ep`.
  - `src/cancel.cc:151-154`: load `cancelled`, then plain `return state->reason`.
  - Public API `include/csp/cancel.h:46`; `STABILITY.md` lists `cancel_reason` as Stable. Callers include `src/io.cc:29`, `src/timer.cc:39,57`, `src/tls.cc:364`, and `test/cancel.test.cc`.
  - Previously confirmed as Fable-5 F2 (`docs/audit/fable-2026-07.md`). Not in 🎯T46’s closed bug list. Still present at HEAD.
- **Mechanism:** a poller on another OS thread can observe `cancelled == true` before `reason` is written (null reason / missed cancel) or concurrently copy a non-atomic `std::exception_ptr` (data race). Channel-wakeup `done()` paths pick up additional locking from the channel protocol; the documented polling API does not.
- **Blast radius:** any imp that polls `cancel_reason()` under `maxprocs >= 2` without waiting on `done()`.
- **Counterevidence checked:** existing cancel tests retrieve the reason after the cancelling spawn has run (`test/cancel.test.cc:219+`); they do not hammer concurrent poll vs `guard(ep)`. Linux TSan CI would only catch this if a test hit the race. `reason` is not `atomic`.
- **Smallest coherent remediation:** publish `reason` with release/acquire (flag or `atomic<shared_ptr<…>>`) as sketched in the Fable note; add a TSan-facing test with two imps.
- **Verification:** TSan test that fails on the current stores/loads and stays green after the pairing. Assertion that a cancelled scope never yields a null reason to a poller that saw `is_cancel_active`/`cancelled`.
- **Ratchet candidate:** that TSan test in `test/cancel.test.cc` under the existing sanitize job.
